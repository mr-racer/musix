## 1. Зачем

Владелец (2026-11-14): нужна модульная система, чтобы **не переписывать компоненты с нуля** на каждом
следующем экране (библиотека, ассистент, чат), а брать готовые; рефакторить приложение на новый
дизайн-код — ближе к web v2, улучшенный и адаптированный под телефон; дизайн high-end, с живыми
анимациями. «Я не очень знаю, как происходит фронт-энд-разработка на мобиле… можешь сделать так,
как считаешь нужным».

Решения владельца в этом разговоре:
1. **Без двойной работы — проверяем сразу в APK.** HTML-витрины компонентов больше нет: каталог живёт в
   самом приложении.
2. **В библиотеку — только самое широкое**: поведение и общие поверхности — «кнопки открытия модалок,
   логика впрыгивания альбомов, скрытие, дебаунс, вибрация». То, что нужно одному экрану
   (пример владельца — капсула «Моя волна»), остаётся зашитым в экране.
3. **Все экраны, кроме главной, переписываются** под логику web и специфично под телефон — из этой библиотеки.
4. Устройство — **один модуль `core/designsystem`, разложенный по слоям, плюс каталог «Витрина» в APK** (§4).
5. **Экраны с принятым web-эталоном собираются без HTML-макета**: текстовый эскиз телефонной раскладки →
   Compose → APK владельцу. Экраны без эталона — эскиз до сборки (§9.1). Это заменяет для Android
   правило «сначала HTML-макет» из `android-rebuild-design.md` §5.1.

**Охват документа:** устройство системы и план переезда целиком. План реализации пишется на **этап A**
(основа, оболочка, «Витрина», вынос с главной — §8); каждый следующий экран получает свой план после
своего эскиза (§9.1).

**Успех:** новый экран собирается из библиотеки, а код экрана — только то, что у него своё; любой
компонент владелец трогает в «Витрине» на своём Pixel 9 Pro с настоящими пружинами и вибрацией, в обеих
темах; v1-детали уходят вместе с последним экраном, который их использовал.

## 2. Цели, не-цели, анти-цели

**Цели**
1. Библиотека по слоям с явным правилом входа (§5.1) и проверкой границ слоёв тестом.
2. «Витрина» в APK: каждый компонент в изоляции, во всех состояниях, с переключателями темы, анимаций и
   вибрации.
3. Широкие детали главной вынесены в библиотеку; **главная выглядит и ведёт себя так же** (её 92 теста
   зелёные без правок ожиданий).
4. Построены широкие компоненты, которые нужны следующим экранам (§6), — каждый к тому экрану, где он
   впервые нужен.
5. План переезда каждого экрана: что берёт из библиотеки, что оставляет себе, что из v1 уходит (§8).

**Не-цели**
- Перерисовка главной; раскладки будущих экранов (у каждого — свой эскиз в свой черёд).
- Web, Windows-клиент, офлайн-скачивания, смена Haze на другое стекло, Material 3 Expressive как вид.
- Отдельное приложение-каталог (второй APK на телефоне).

**Анти-цели** (провал, даже если «работает»)
- Библиотека заготовок «на всякий случай»: компонент без двух потребителей и не-поведение.
- Две живые версии одного компонента надолго: v1-деталь доживает в `legacy` только до своего последнего экрана.
- Что-то движется в покое, телефон греется; вибрация на обычные тапы; отрисованный глянец.
- «Витрина» видна или стоит что-то обычному пользователю (вход скрыт, код не грузится до открытия).
- Главная меняется от выноса деталей.

## 3. Ограничения

- Стек: AGP 9.4.1, Kotlin 2.4.20, Compose BOM 2026.09.00, Hilt, Navigation 2.10 (type-safe), Media3 1.11,
  Haze 2.1 (`haze-glass`), `graphics-shapes` 1.1.0, `sh.calvin.reorderable` 3.1.0, Coil 3, Roborazzi 1.76,
  `minSdk 24`, `targetSdk 36`. Новые зависимости — только по §7.
- Токены — только `design/tokens/*.json` → `make design`; `design/gen/android/MusixTheme.kt` руками не трогать.
- Только `transform`/`opacity`/`graphicsLayer` в анимациях; в покое — ни одного кадра; цель — частота экрана
  (Pixel 9 Pro, 120 Гц). Размытие — `RenderEffect` на API 31+, ниже — без него.
- Вибрация — словарь `HapticCue` (9 видов), общий шлюз (тик ≥ 45 мс, вид ≥ 120 мс), только от пальца.
- Reduced motion (системная «Без анимаций») — у каждого компонента: состояние меняется сразу или кроссфейдом ≤ 120 мс.
- Цели касания ≥ 48 dp. Код, комментарии, коммиты — английский; UI и документация — русский.
- Prod — только чтение; GPU — prod и llama-server; эмулятор `musix-rebuild-emu` (5556) и тесты — на CPU.
  Снимки реальной библиотеки — только `/mnt/data/musix-snapshots/`, не в git.
- `versionCode` и `versionName` поднимаются вместе на каждый APK; публикация для всех — только по слову владельца.

## 5. Устройство библиотеки

### 5.1 Правило входа

Деталь входит в `core/designsystem`, если выполнено одно из двух:
- **это поведение** — модификатор или держатель состояния без собственного вида (нажатие, вибрация,
  дебаунс, впрыгивание, скрытие, перелёт, жест);
- **её берут минимум два экрана** из плана переезда (§8).

Иначе она живёт в экране как `internal`. Когда второму экрану понадобится деталь первого, она
**переезжает** в библиотеку (не копируется) — тем же коммитом, что и второй экран.

У каждой детали библиотеки: KDoc (английский) с русским именем и источником (web-файл или раздел
дизайн-кода); карточка в «Витрине»; Roborazzi-снимок всех состояний в обеих темах; объявленные вибрация
и нагрузка (что двигается и когда затихает).

### 5.2 Слои и пакеты

`ru.musixai.app.core.designsystem.<слой>`; каждый слой импортирует только нижние.

| Слой | Пакет | Что в нём |
|---|---|---|
| Основа | корень `core.designsystem` (сделано так вместо подпакета `foundation`: генерируемая `MusixTheme.kt`, иконки и импорты главной остаются на месте) | тема v2 (роли текста, цвета, отступы, радиусы, тени), поверхности float/plate/glass, иконки, раскладочные модификаторы |
| Движение | `motion` | пружины, впрыгивание, появление/скрытие, смена содержимого, перелёты, смена страниц, цикл, засыпающий в покое |
| Жесты и отклик | `gesture` | нажатие, дебаунс, вибрация, тяга с резинкой, смахивание, перестановка, шапка по прокрутке, «вторым нажатием» |
| Поверхности | `surface` | шит, перетекающее меню, тосты, стекло |
| Контролы | `control` | круглая кнопка, пилюля, ссылка, вкладки, сегменты, переключатель, иконка-морф, перетекающая кнопка, поле |
| Содержимое | `content` | обложка, стопка обложек, строка трека, состояния экрана, беседа (реплика, поле беседы, шаги), событие, мастер |
| (уходящее) | `legacy` | v1-детали до их последнего экрана, `@Deprecated` с указанием замены |

Пакет `component` (сейчас) расформировывается по слоям; публичные имена, которые берёт главная,
сохраняются или меняются одним коммитом вместе с её импортами.

### 5.3 Что остаётся в экранах (по правилу §5.1)

| Экран | Остаётся своим |
|---|---|
| Главная | капсула «Моя волна» и панель настройки (`WaveCapsule`, `TunerPanel`), сфера-мембрана (`MembraneOrb`, `Membrane`), билет альбома дня, бусины, налитая кнопка, финал, небо с линзой (`Sky`), `HeroSpec`, вайбик |
| Плеер | волнистый seek с разделами, листание обложки с физикой, peek-строки «О песне»/«Далее», огонёк/вода со всплеском, «винил», значок Lossless |
| Библиотека | рельс групп, раскладка «Стены», плёнка «не слушал», «Пластинка дня», графики статистики, стикеры ачивок |
| Артист | кадр с фото и размытием, лавр, ось дискографии, уровень «Ты и …», карточка игры |
| Ассистент | сфера «Хрусталь», орбита вопросов, карусель, карточки ответов по типам, сноски `[n]` |
| Вход | `CodeField` (код с сайта) |

Кандидаты, которые решаются на своём этапе по правилу: плитка альбома, заголовок группы (библиотека —
есть ли второй потребитель), сфера-мембрана (если её физику возьмёт сфера ассистента — переезжает).

### 5.4 Вынос с главной (без изменения вида)

| Что | Куда | Как |
|---|---|---|
| `MorphMenu`, `Morph`, `morphSurface`, `rememberMorph` | `surface` | как есть, `internal` → `public`; затем обобщение (§6, №24) |
| цикл кадров мембраны и неба (идёт, пока шаг возвращает true; паркуется) | `motion` — `rememberParkingLoop` | `MembraneOrb` и `Sky` переходят на общий цикл |
| `Modifier.bleed` (ряд выходит под поля колонки) | `foundation` | как есть |
| складывание «Слушать» (`shrinkHorizontally` + scale + fade) | `motion` — `Reveal.fold` | `AlbumTicket` берёт общий вариант |
| появление бусин лесенкой 20 мс | `motion` — `cascade` | `AlbumTicket` берёт общий |
| `PlayPauseGlyph` | `control` — первая форма `MorphIcon` | имя сохраняется как обёртка до переезда плеера |

Проверка выноса: тесты `feature/home` (92/92 по журналу r4) проходят без изменения ожиданий; Roborazzi
главной в обеих темах совпадает до и после; на эмуляторе — «Слушать», поиск, тюнер, запуск Потока.

### 5.5 «Витрина» — каталог в APK

- **Модуль** `:feature:catalog`, зависит от `core/designsystem` и `core/data` (только чтение). В release-APK
  (владелец тестирует release-сборки); при старте приложения ничего не создаёт и не читает — только при
  открытии экрана.
- **Вход**: Настройки → семь нажатий на строку версии → «Витрина»; признак хранится в DataStore, пункт
  появляется в настройках. Для разработки — deep link `musix://catalog` (adb на эмуляторе).
- **Реестр** `CatalogEntry(id, имя, слой, потребители: List<Screen>, вибрация, нагрузка, состояния,
  demo)`; `Screen` — экраны плана §8 по отдельности: Оболочка, Главная, Мини-плеер, Плеер, Чат по треку,
  Библиотека, Статистика, Разворот, Артист, Плейлист, Ассистент, Настройки, Импорт и загрузка, Игра,
  Вход. Один список даёт: карточки «Витрины», параметризованный Roborazzi-тест всех состояний в обеих
  темах и тест правила входа (у каждой записи ≥ 2 потребителя или слой «поведение»).
- **Вид** (сама «Витрина» собрана из библиотеки — первая проверка, что ею удобно пользоваться):
  ```
  ╭ Витрина ─────────────────────── ( ◐ ) ( ⏸ анимации ) ( 〰 вибрация ) ╮
  [Все] [Библиотека] [Ассистент] [Чат] [Плеер] [Артист] …   ← фильтр по экрану
  Движение                                                  ← слой: крупный заголовок в потоке
    Впрыгивание лесенкой                         ↻ ещё раз
    ┌ живое демо: 12 обложек влетают лесенкой ┐
    └─────────────────────────────────────────┘
    [норма] [длинный список] [без анимаций]                ← состояния
    Берут: Библиотека · Разворот · Артист · Ассистент
    Вибрация: нет · В покое: 0 кадров ✓                    ← живой счётчик кадров
  ```
  Фильтр по экрану показывает план переезда прямо в приложении: что этот экран возьмёт. Демо-данные —
  обложки и песни из **собственной библиотеки владельца на устройстве** (локальное зеркало `core/data`);
  без входа или без сети — сгенерированные обложки в цветах палитры. В git реальных обложек нет.
- **«Медленно ×4»** для разглядывания пружин — если пружины читают общий масштаб (`LocalMotionScale`,
  через `MusixSprings`); если не выйдет чисто — вместо переключателя подсказка про системную «Скорость
  анимации» (решает строитель).
- **Счётчик кадров** на карточке: сколько раз перерисовалось **само демо** за последнюю секунду; через
  ~1,5 с после жеста — 0. Считает счётчик перерисовок на собственном слое демо (`drawWithContent`, не
  состояние), а не кадры окна и не `withFrameNanos`: иначе он сам просит кадры, а смена его подписи
  засчитывается как движение — и «0» никогда не наступит.
  **Сделано иначе (2026-11-14):** один индикатор в шапке — кадры, которые окно действительно нарисовало
  за секунду (`FrameMetrics`, сам кадров не просит). Счётчик на слое демо промахивается: анимация
  дочернего `graphicsLayer` перерисовывает только свой слой, а `drawWithContent` родителя не вызывается.
  Петлю «подпись меняется → это кадры → подпись меняется» сначала поймали на эмуляторе (0 → 2 → 2 → 0),
  потом убрали: в секунду после смены подписи её ~2 кадра вычитаются. Проверено `dumpsys gfxinfo`: в покое
  0 кадров за 5 с, индикатор стоит на «в покое».

### 5.6 Границы слоёв

Unit-тест `LayerRulesTest` читает исходники `core/designsystem` и `feature/*`:
- слой импортирует только нижние (`foundation` ← `motion` ← `gesture` ← `surface`/`control` ← `content`);
- `legacy` импортируют только файлы из явного списка нынешних потребителей; список только сокращается
  (переехавший экран убирается из него, новый файл туда не попадает);
- `feature/*` не импортируют друг друга (уже так; тест фиксирует).

### 5.7 Контракт компонента

- `modifier: Modifier = Modifier` — первый необязательный параметр; содержимое — слотами
  (`content: @Composable …`), а не десятком флагов.
- Жестовые компоненты — пара «держатель состояния + отрисовка» (`rememberSheetState`, `Morph`), чтобы
  экран управлял ими и тестировал без Hilt (как `MiniPlayerBar`).
- Вибрация — только через `LocalMusixHaptics`, `fromUser = true` только для пальца.
- То, что рисует оболочка (шит в `SheetHost`), носит `CompositionLocal` **места объявления** — тему,
  вибрацию, «без анимаций» (как `Popup`/`Dialog`). Найдено в «Витрине»: шит из тёмной карточки
  открывался в светлой теме оболочки.
- Скорость броска у того, что едет под пальцем (шит, тост, шайба), считается по пути пальца, а не по
  локальным координатам: они едут вместе с узлом, и скорость выходила около нуля — бросок не срабатывал.
- Reduced motion читается через `rememberReducedMotion()` один раз в компоненте.
- В покое ничего не компонуется и не рисуется заново; бесконечные анимации — только у объявленного
  «живого» (EQ-полоски, перелив шага), и только пока видно и активно.
- Тест-теги — константы рядом с компонентом.

## 6. Состав библиотеки

«Когда» — где компонент строится: **0** — основа до любого экрана, **1** — оболочка до любого экрана,
иначе — в начале этапа названного экрана (§8). «Есть» — уже в коде, «главная» — выносится (§5.4),
«новый» — пишется. Номера 48–52 добавлены после этапа A (плеер 2.4, 2026-11-15) и стоят в своих слоях.

### Основа (`foundation`)

| № | Компонент | Что делает | Берут | Откуда | Когда |
|---|---|---|---|---|---|
| 1 | Тема v2 | **новый** набор ролей текста (`MusixTheme.text`) по `MusixScale` (cap 11 / sm 13 / body 15 / lead 18 / h 24 + заголовки экранов): Geist — UI, Noto Sans — читаемый текст, JetBrains Mono — время и счётчики (tabular). ## 9. Как идёт работа

### 9.1 Рутина одного экрана (заменяет §5.1 спеки 2026-11-13 для Android)

1. **Эскиз в чате**: текстовая схема телефонной раскладки, состояния (пусто, загрузка, ошибка, длинный
   текст, 1 и 1000 элементов), шиты и меню, входы/выходы; список «берёт из библиотеки / строит в
   библиотеку / своё». Экраны с эталоном — владелец смотрит и может поправить; без эталона — ждём «да».
2. **Библиотека прежде экрана**: недостающие широкие компоненты строятся первыми, каждый с карточкой
   «Витрины» и снимками.
3. **Экран** собирается из библиотеки; своё — `internal` в модуле экрана.
4. **Проверка** (§10), затем APK владельцу (новый `versionName`). Его слова — в
   `design/code/preferences.md` в тот же день; доводка.
5. v1-детали, у которых не осталось потребителей, удаляются тем же этапом.

### 9.2 Поставка

APK — release-сборка с релизным ключом, ставится обновлением основного приложения на телефон владельца:
файл на dev-адресе Tailscale (как APK этапа 0) или по adb с его ПК. Публикация для остальных — только по
его слову (`musix-apk-release`). Версии: этап A — 2.3.0, каждый следующий экран +0.1, правки внутри
этапа — +0.0.1 (*моё решение*).

### 9.3 Записи в дизайн-коде

- `design/code/components.md` — раздел «Android: библиотека» генерируется из реестра «Витрины» или
  ведётся руками по нему (решает строитель); старые разделы «Принятые компоненты Android» и «Предложено
  — главная r2» ссылаются на него.
- `design/code/README.md` / `roadmap.md` — правило §9.1 (решение владельца 2026-11-14).
- Локальные заметки `C:\musix\CLAUDE.md` — строка про этот документ.

## 10. Проверка

На каждом этапе:
- `./gradlew testDebugUnitTest` во всех модулях; Roborazzi всех карточек «Витрины» в обеих темах
  (`recordRoborazziDebug` при намеренной смене вида, `verifyRoborazziDebug` в остальное время);
  `LayerRulesTest` и тест правила входа по реестру.
- **«В покое тихо»** тестом: у каждого анимированного компонента после жеста и ~1,5 с Compose становится
  idle (нет ожидающих кадров); у «живых» — idle при паузе или вне экрана.
- Release-сборка с R8 (минификация не ломает «Витрину» и экраны); smoke Android Auto, виджетов Glance и
  «Слушать на…».
- Эмулятор `musix-rebuild-emu` (5556) на трёх размерах (360×780, 412×915, 448×998 dp-эквиваленты), обе
  темы; главная после выноса — те же сценарии, что в журнале r4.
- На телефоне владельца: вибрация каждой карточки «Витрины», плавность 120 Гц, нагрев за 10 минут
  воспроизведения (`dumpsys thermalservice`). Эмулятор на CPU плавность не показывает — заявлять её по
  эмулятору нельзя.

## 11. Решено мной (владелец может поправить)

- «Витрина» — модуль `:feature:catalog` внутри release-APK, вход — семь нажатий на версию + deep link.
- Демо-данные «Витрины» — собственная библиотека на устройстве; без неё — сгенерированные обложки.
- Один реестр компонентов даёт карточки, снимки и тест правила входа.
- v1-детали — в пакет `legacy` со списком потребителей, который только сокращается.
- Порядок экранов §8 и нумерация версий §9.2.
- `CodeField`, волнистый seek, рельс, peek-строки, значок Lossless остаются в экранах по правилу §5.1.
- На этапе C экран поиска Android уходит, его место занимает ассистент — как на web (`roadmap.md`:
  ассистент «replaces today's search screen»); «Весь поиск →» с главной ведёт в ассистента с вопросом.
- Новые роли текста и роль нажатия по умолчанию сделаны так, чтобы главная и v1-экраны не менялись до
  своего переезда.
- Web-ассистент `/assistant` считается эталоном, хотя его нет в таблице одобренных макетов `README.md`:
  он собран по `design/reference/assistant/` и работает.

  `PageFocus` в `NavHost`: вкладки — столбцом по их порядку, открытие — вперёд, «назад» и жест «назад» —
  назад; каждая страница размывается на время смены (`pageFocusBlur`, API 31+). Разворот (`dialog`)
  рисует свой перелёт, как раньше.
- «Витрина» `:feature:catalog`: 30 карточек по слоям, фильтр по экранам плана, переключатели темы,
  «без анимаций», вибрации, индикатор кадров (§5.5). Демо-данные — выдуманные альбомы со своими
  градиентами (не библиотека владельца: без сети и без входа, снимки не трогают реальную фонотеку).
  Вход: Настройки → «Версия …» семь раз за 3 с → «Витрина компонентов» (флаг `catalog` в
  `datastore/interactions.json`); `musix://catalog` — и с холодного старта, и в открытое приложение.
- Тесты — только ключевые (решение владельца): `LayerRulesTest`, `GestureLogicTest` (7),
  `CatalogRegistryTest` (правило входа + уникальность id). Оба теста правил проверены мутацией. Всего
  103/103; release-сборка с R8 собирается.
- Эмулятор (2.3.0-dev): «Витрина» в обеих темах, шит, тосты, меню, дверь в настройках; в покое 0 кадров.

**Отличия от плана выше и почему**
- Нет параметризованных Roborazzi-снимков карточек — владелец просил только ключевые тесты.
- «Медленно ×4» не сделано; вместо него «без анимаций» через `LocalReducedMotionOverride`.
- `AnchoredDrag` не выделен в держатель: шит собран на `rubberBand` + `shouldClose`; держатель появится,

- Заготовка (`Skel`) осталась v1: читает анимацию в композиции — перекомпоновка каждый кадр, пока
  видна. Переделать на чтение в отрисовке — с этапом B.
