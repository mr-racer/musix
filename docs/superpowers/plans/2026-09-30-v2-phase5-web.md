# Phase 5 — Web client: plan

> Native execution, blocks in order, each ending with its check and a commit (Russian
> subject). Tests only for clear functionality: about 6 for this phase (the project budget
> is ~100; 79 are spent).

**Spec:** `docs/superpowers/specs/2026-09-29-v2-phase5-web-design.md`.
**Starting point:**
- the TS client config (`v2/contracts/codegen/ts`: openapi-typescript + openapi-fetch);
- `v2/design/gen/web/tokens.css` and `design/components/*.md`;
- v1's SPA for the look (`frontend/src`, `frontend/packages/musix-ui/styles.css`);
- the Android app for v2 API usage patterns (manifest, «Поток», listens, sync);
- golden desktop 1440×900 + phone 412×915 (`/mnt/data/musix-snapshots/golden/2026-09-29`);
- api-snap on the migrated data (`musix_mig`).

**Goal:** `v2/web/`, a lean SPA on API v2. It covers listening (home, «Поток», player,
library, search, artist, settings, uploads) and the owner's admin. The §5 budgets are met,
and the owner has a screenshot review.

## Global constraints

- Node 22 (host). Caches go on `/mnt/data`: `npm_config_cache=/mnt/data/.cache/npm` and
  `PLAYWRIGHT_BROWSERS_PATH=/mnt/data/.cache/ms-playwright`. The system disk is 99% full.
- Stack per spec §1:
  - TS strict, React 19, Vite;
  - TanStack Router (file routes, auto code-split) + Query + Virtual;
  - Zustand for the player;
  - Dexie for the `/sync` mirror;
  - CSS Modules on `tokens.css`, no inline style objects.
- Out of scope (spec §2): assistant, quiz, stats.
- The service worker caches the shell and hashed assets only. It never touches `/api`,
  `/m/` or `/i/`.
- Admin routes are their own chunk and never load for members. The server enforces
  owner-only on every admin endpoint regardless.
- Users never see other users' tracks: every admin view shows counts, never another
  account's titles.
- Web auth: no tokens in `localStorage`.
  - The refresh token is an `HttpOnly; Secure; SameSite=Strict` cookie on
    `/api/v2/auth`.
  - The access token lives in memory only.
  - A reload does one refresh.

## Block 1 — Server add-on + scaffold + auth

- **Server:**
  - `GET /instance` (open): `setupRequired`, `mode`, LLM availability.
  - Web cookie mode on `/auth/{setup,login,register,refresh,logout}`:
    - `platform=web` → the refresh token goes in a Set-Cookie, not the body;
    - refresh reads the cookie when the body has none.
  - `GET /admin/members`: role, email, invite, created/last login, `index_root`, premium,
    counts (tracks, listens, likes).
  - `PATCH /admin/members/{id}`: `index_root` (under `library_roots`), `premium`.
  - `DELETE /admin/members/{id}`: v1 delete. It revokes devices and removes the account's
    rows through the existing account purge (or a new one).
  - `GET/PUT /admin/instance`: name, registration by invite only.
  - `GET /admin/ops`:
    - queue depths per queue/status;
    - media dir bytes vs `MUSIX_MEDIA_BUDGET_GB`;
    - rendition coverage per tier;
    - media files missing probe/loudness;
    - a few `/metrics` counters.
  - `POST /admin/renditions/backfill` → `media:backfill`.
  - AI policy = v1 `premium`: members without it get 403 on assistant and track-chat
    turns. The owner is always allowed.
  - openapi regenerated.
- **Web:** `v2/web/` scaffold:
  - generated client with an auth middleware (single-flight refresh on 401);
  - `tokens.css` + fonts (the Android OFL set);
  - root layout with the tab/side nav from v1;
  - login / register (invite) / setup screens;
  - the WS client (auth message, `lastSeq`, Query invalidation).
- **Dev and prod serving:**
  - nginx `location /` serves `web/dist` with an SPA fallback (hashed assets
    `immutable`, `sw.js` and `index.html` `no-cache`);
  - `make web`, `make web-dev` (Vite proxy → api-snap).
- **Done when:** login against api-snap works in the browser, and a reload stays signed in
  with no token in storage.
- **Tests (2, server):**
  - admin endpoints refuse a member (403), and the members list carries no titles;
  - the web refresh cookie rotates and a reused one revokes the family.

## Block 2 — Player

- **What:**
  - Zustand store over one `<audio>`, plus a hidden preloader `<audio>` for the next track
    once the current one passes 50%;
  - `POST /playback/manifest` for current + next 5;
  - tier from `navigator.connection` else the setting;
  - on a media error → re-resolve, then the fallback;
  - Media Session: metadata, artwork, actions, position state;
  - normalization:
    - desktop: a `GainNode`, with the context created in the first play gesture;
    - mobile UA: element volume attenuation only;
  - listens:
    - accounted like `ListenAccumulator` (the Android port);
    - batched to `events/listens:batch`, flushed on `pagehide` with `fetch(keepalive)`;
    - an IndexedDB outbox survives a closed tab;
  - «Поток» via `/stream/next`; list autoplay via `/stream/autoplay`; огонёк/вода via
    `/tracks/{id}/signals`.
- **Done when:** in Chromium, «Поток» plays across 3 boundaries with the tab in the
  background, listens land on the server, and OS media keys work.
- **Test (1, Vitest):** listen accounting + boundary: the preload arms at 50%, end reasons
  and early-skip.

## Block 3 — Listening surfaces

- **What**, in order:
  1. home (`GET /home`, one request after the shell);
  2. player (full view, lyrics synced, facts rail, credits, queue reorder/remove,
     envelope wave);
  3. «Поток» settings;
  4. library:
     - albums / artists / tracks / playlists over the Dexie mirror;
     - lists virtualized with TanStack Virtual;
     - playlist edits;
  5. search (sections, year/sound chips);
  6. artist atlas;
  7. settings: quality, normalization, theme, language, devices;
  8. uploads: drag-and-drop → sha256 in a Worker → resumable PATCH chunks.
- **Subtleties:**
  - desktop and phone layouts from the golden shots;
  - the Dexie mirror is wiped on sign-out or an account change (as on Android).
- **Done when:** every screen renders on migrated data in both themes at both sizes, and an
  upload of a real file becomes playable.
- **Test (1, Vitest):** the sync mirror applies a full page then a delta with a delete, and
  sweeps on resync.

## Block 4 — Admin

- **What:**
  1. setup wizard (v1 `SetupWizard`: owner account, mode, LLM, library folder);
  2. members + invites (create / copy / revoke, grant folder, premium, delete with a typed
     confirm);
  3. AI policy + LLM endpoint (masked key);
  4. instance settings;
  5. library management (rescan per granted folder; indexing progress and the rendition
     backlog over WS job events);
  6. Yandex import (the device flow, like Android);
  7. ops page.
- **Done when:** on a fresh dev DB, setup → invite → register a member in a second browser
  context → grant folder → rescan with live progress.
- **Test (1, Playwright flow):** setup → invite → member registers → member sees no admin
  chunk request and gets 403 on `/admin/members`.

## Block 5 — Budgets, flows, review

- **What:**
  - Lighthouse (desktop LAN + an LTE profile) on home: LCP, INP (via a Playwright
    interaction trace), JS per route (gzip, from the Vite manifest), home requests;
  - 60 fps scroll of the 6k library (Playwright trace, frame times);
  - the Playwright flow «login → play → listen recorded»;
  - the screenshot review page: v2 next to golden, desktop + phone, both themes, plus the
    budget table.
- **Done when:** the budget table is filled and the review page is published.
- **Test (1, Playwright flow):** login → play → a listen is recorded on the server.

## Review focus (end of phase)

1. Background-tab playback across boundaries: the preloader swap, a Media Session with
   stale metadata, a suspended AudioContext on mobile (must never be used there).
2. Auth: a parallel 401 storm → one refresh; a reused cookie → sign-out; no token ever in
   storage or URLs.
3. Admin isolation: a member never downloads the admin chunk, and every admin endpoint is
   403 for them. Admin views show no other account's titles.
4. The service worker never intercepts `/api`, `/m/` or `/i/` (Range requests on signed
   URLs).
5. Account switch in the same browser: the Dexie mirror, the player queue and the outbox
   hold nothing from the previous account.
