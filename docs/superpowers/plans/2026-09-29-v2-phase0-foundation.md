# Phase 0 — Foundation: plan

> For the executor: **native execution** (one agent, in order), one whole-branch review at
> the end. Each block ends with an acceptance check. Run the check, then commit
> (conventional prefix, Russian subject). No step-by-step TDD script: tests are written
> with the code, and the check says what must be green.

**Spec:** `docs/superpowers/specs/2026-09-29-v2-phase0-foundation-design.md`. Also:
- program §5;
- the stream spec §2 and §10 (block D);
- the throwaway spike `/mnt/data/musix-v2-staging/recsys-spike/`;
- the staged e2e suite `/mnt/data/musix-v2-staging/e2e-v1/`.

**Branch:** `feature/musix-v2`. **Goal:** exit criteria 1–4 of the spec.

## Global constraints

- **v1 is frozen:** never edit `app/`, `frontend/`, `scripts/`, `tests/` or the v1 compose
  files. Reading and importing v1 code is fine.
- **Prod is read-only:**
  - never restart or modify `musix`, `qdrant` or `searxng`;
  - never write into their volumes;
  - no load tests against prod.
- **Prod data stays on the machine:** snapshots, reports with raw rows and mood labels live
  under `/mnt/data/musix-snapshots/`, never in git.
- **The GPU belongs to prod + llama-server** (~3 GB free). Anything of ours that loads
  models runs with `FORCE_CPU=1`, or is capped (`torch.cuda.set_per_process_memory_fraction`).
- **Dev ports** are `18xxx`, bound to `127.0.0.1` only. The compose project name is
  `musix-v2-dev`, with its own volumes and network.
- **Verified stack** (2026-09-29):
  - Python 3.13, uv 0.11.26;
  - fastapi 0.141, uvicorn 0.54, pydantic-settings 2.15, sqlalchemy 2.1 + asyncpg 0.31,
    alembic 1.20, procrastinate 3.10 (psycopg 3.3), qdrant-client 1.19, structlog 26.1,
    httpx 0.28;
  - dev: ruff 0.16.9, mypy 2.3 (`--strict`), pytest 9.1 + pytest-asyncio 1.4,
    testcontainers 4.15;
  - images: `postgres:18` (18.6), `qdrant/qdrant:v1.18.2` (= prod), `nginx:1.29-alpine`,
    `python:3.13-slim`, `ghcr.io/astral-sh/uv:0.11.26`.
- `docs/` is gitignored: specs and plans are added with `git add -f`.

## A. Server skeleton, dev stack, CI (exit criterion 4)

**Do:**
- **`server/`** (uv project, package `musix` in `src/`):
  - `settings.py`: pydantic-settings, prefix `MUSIX_`, one `Settings`;
  - `infra/db.py`: async engine and a ping;
  - `infra/queue.py`: the Procrastinate app;
  - `api/app.py`: `create_app()`, routes `GET /api/v2/health` (liveness) and
    `GET /api/v2/ready` (Postgres `select 1` + Qdrant `get_collections`; 200, or 503 with
    the failing check);
  - `ml/app.py`: `GET /health` → `{status, device}`;
  - `workers/app.py`: a module-level `app` and one `ping` task.
- **`server/migrations/`** (Alembic): `0001_baseline` creates `pg_trgm`, `unaccent`,
  `pg_stat_statements` and the Procrastinate schema.
- **`contracts/openapi.json`:** generated by `python -m musix.api.openapi_export` and
  committed. A contract test fails on drift.
- **`server/Dockerfile`:** one image for three commands (api / worker / ml), plus a
  one-shot `migrate`.
- **`deploy/compose.dev.yml`:**
  - postgres 18432, qdrant 18333, api 18000, ml 18002, nginx 18080 proxying `/api/v2` →
    api;
  - a worker;
  - `migrate` runs before api and worker.

  `deploy/compose.dev.gpu.yml` adds the GPU reservation to `ml` and sets
  `MUSIX_ML_DEVICE=cuda`. The v2 nginx config lives in `deploy/nginx/v2-dev.conf`; v1's
  `deploy/nginx/musix.conf` is untouched.
- `clients/` and `design/` are not created as empty dirs: they appear in block F and in
  phases 4, 5 and 7.
- **Root `Makefile`:** `dev`, `down`, `logs`, `test`, `lint`, `openapi`, `check` (lint +
  mypy + tests + openapi drift). Later blocks add `snapshot`, `gates`, `bench`, `design`.
- **Tooling:**
  - `.github/workflows/v2-server.yml` (paths `server/**`, `contracts/**`), using
    `actions/checkout@v7` and `astral-sh/setup-uv@v10.2.0`: ruff check + format check, mypy,
    pytest (unit + integration via testcontainers + contract);
  - `.pre-commit-config.yaml`: ruff-pre-commit `v0.16.9`, `files: ^server/`;
  - `.gitignore` gets `.venv/`, `.mypy_cache/`, `.ruff_cache/`, `.pytest_cache/`,
    `tools/**/.run/`.
- **The e2e suite** moves to **`tools/e2e-v1/`**:
  - `seed.py` generates the three 150 s test tones with ffmpeg
    (`-f lavfi -i sine=…:duration=150 -b:a 320k`) instead of committing 18 MB of mp3;
  - `serve.py` / `seed.py` import v1 from the repo root instead of a `code/` copy;
  - `env.sh` points at `tools/e2e-v1/.run/`;
  - the README says how to run it: env `/mnt/data/envs/musix-e2e`, `frontend/dist` built
    locally with `npm run build` (that builds v1, it does not edit it).

**Subtleties:**
- **One DSN, three forms.** `MUSIX_DATABASE_URL=postgresql://…` is the libpq form and is
  what Procrastinate's `PsycopgConnector(conninfo=…)` takes. SQLAlchemy uses
  `postgresql+asyncpg://`, and Alembic uses sync `postgresql+psycopg://`. Derive the three
  as `Settings` properties and unit-test the derivation.
- **The Procrastinate schema in Alembic:** the SQL is a 20 KB multi-statement script that
  contains `%`. asyncpg prepares statements (it fails), and SQLAlchemy `text()` or
  `exec_driver_sql` may parse the placeholders. Execute it on the raw psycopg connection,
  which is verified to work:

  ```python
  op.get_bind().connection.dbapi_connection.execute(SchemaManager.get_schema())
  ```

  `downgrade()` of the baseline raises; say so in its docstring.
- **pg_stat_statements** needs `-c shared_preload_libraries=pg_stat_statements`, both in
  compose and in the testcontainers fixture (`.with_command(...)`).
- **testcontainers imports:** `testcontainers.community.postgres.PostgresContainer(...,
  driver=None)` (the old `testcontainers.postgres` is deprecated) and
  `testcontainers.community.qdrant.QdrantContainer("qdrant/qdrant:v1.18.2")`. Use one
  session-scoped container per kind.
- **The root `pytest.ini` belongs to v1.** Put `[tool.pytest.ini_options]` in
  `server/pyproject.toml`, so `cd server && uv run pytest` gets `server/` as the rootdir.
- **Worker health:** the compose healthcheck is
  `procrastinate --app=musix.workers.app.app healthchecks`. The integration test defers
  `ping` and runs `app.run_worker_async(wait=False)`, then asserts the job's status via
  `app.job_manager.list_jobs_async(task=...)`.
- **Tests of `/ready`:**
  - the 503 path is a unit test with the checks overridden;
  - the 200 path is an integration test against the containers, using `TestClient` as a
    context manager so the lifespan runs.
- **Slim images have no curl.** Healthchecks use `python -c "import urllib.request…"`.
- **`ml` does not import torch in phase 0.** Its device comes from `MUSIX_ML_DEVICE`, and
  torch arrives with phase 2 as an optional dependency group.

**Done when:**
- `make check` is green;
- `make dev` shows every service healthy, and `curl 127.0.0.1:18080/api/v2/ready` → 200;
- `docker ps` shows v1's `musix` untouched (same container id, ports 8000/6333);
- the e2e suite from `tools/e2e-v1/` passes its 4 tests against the repo's v1.

## B. Prod snapshot — `tools/snapshot/`

**Do:** `make snapshot` runs `tools/snapshot/take.py` →
`/mnt/data/musix-snapshots/<YYYY-MM-DD>/`, containing:
- `metadata.db`;
- `qdrant/<collection>.jsonl.zst` (points with all vectors and payloads) plus
  `collections.json` (the configs);
- `manifest.json` (every media file and cover: path, size, mtime, sha256);
- `derived.json` (a manifest of `cache/transcoded` and `frontend/covers`).

`make snapshot-restore SNAP=<date>` runs `tools/snapshot/restore.py`: it loads a snapshot's
Qdrant part into the dev Qdrant (18333) and copies `metadata.db` to a working copy for a v1
driver.

**Subtleties:**
- **SQLite:** open the host file `/home/ivan/musix-db/metadata.db` with `?mode=ro` and use
  `sqlite3.backup()`, which is WAL-safe. Check read permission first; if the file is
  root-owned, back up through `docker exec musix` into stdout, as `extract.py` did in the
  spike. Never write next to the prod DB.
- **Qdrant without writing to prod:** the snapshot API would write snapshot files into
  prod's storage. **Scroll** instead: ~9k points, seconds.
  - Prod's Qdrant port is not published, so run the taker in a throwaway container on
    network `lyrics-search_default` (the v2 image, read-only mounts), or via
    `docker exec musix` as the spike did.
  - Restore recreates each collection from `collections.json`, including the sparse `bm25`
    config with the IDF modifier, and upserts in batches.
- **Hash cache:** `/mnt/data/musix-snapshots/.hashcache.sqlite` keyed by (path, size,
  mtime). The first run reads ~237 GB (~25 min); later runs take seconds.
  - Paths are recorded as the container sees them (`/music/...`, `/app/media/...`),
    because Qdrant payloads and `track_metadata` use those. Record the host mapping
    `/music → /mnt/data/music` and `/app/media → /mnt/data/lyrics-search/media` in the
    manifest header.
- The snapshot dir is `chmod 700`.

**Done when:**
- a snapshot for today exists;
- restore brings up the collections in the dev Qdrant with point counts equal to prod;
- a second `take` reuses the hash cache (< 1 min for the manifest).

## C. Search gates 4.1–4.3 + 4.5 + 4.6 — `tools/gates/`

**Do:**
- **`make gates TARGET=v1 SNAP=<date>`:**
  - builds the fixtures once per snapshot (lyric 300 × 4 kinds, sound 80 prompts, catalog
    300);
  - runs the **v1 driver** in-process;
  - writes `tools/gates/report/<date>-v1.{md,json}`, numbers only.
- **`--target v2`** is an HTTP driver with the same interface, a stub until phase 2.
- **4.5:** thin wrappers that run `scripts/eval_facts_prompts.py`, `scripts/eval_bio_prompt.py`
  and the routing fixtures of `tests/docker/test_assistant_routing.py`, and fold their
  numbers into the same report.
- **4.6:** the migration-gate scaffold, i.e. the report section, plus a per-entity count and
  checksum helper that phase 3 fills in.

**Subtleties:**
- **The v1 driver** runs in its own venv (`/mnt/data/envs/musix-gates`, built from
  `requirements.txt`), because v1 imports must not touch the server env.
  - Env: `FORCE_CPU=1`, `QDRANT_URL=http://127.0.0.1:18333` (the restored snapshot), and
    `MUSIX_METADATA_DB` = the working copy.
  - It calls v1's search services directly (lyrics RRF, CLAP text → audio,
    `library_catalog`), per account collection. No HTTP, no auth.
  - On CPU the ~1.5k query encodes take minutes. Run the encoder once per query and cache
    the vectors by the (model, text) hash, so v1 and v2 runs share them and re-runs are
    instant.
- **Fixture derivation:**
  - use the snapshot's own lyrics;
  - the `translit` kind covers only Russian lines, with one fixed translit table (GOST-like,
    no randomness);
  - typos are seeded with `random.Random(snapshot_date)` so fixtures are stable;
  - fixtures are stored under the snapshot dir, not in git.
- **Sound gate:** the prompts come from the library's `sonic_tags` and genres. Overlap@10 is
  against v1's own lists, so v1-vs-v1 must come out at 1.0; that is a self-check.
- **4.5 needs the LLM endpoint** (LM Studio or llama-server). Record the model id in the
  report, and mark the section `skipped` rather than failing when the endpoint is down.

**Done when:**
- `make gates TARGET=v1` writes a complete report;
- a re-run gives identical numbers (determinism);
- v1-vs-v1 sound overlap = 1.0.

## D. «Поток» harness — `tools/recsys-eval/` (spec 4.4)

**Do:** rebuild the spike as a small package reading the snapshot.
- **Modules:**
  - `data` (events with outcomes, listening sessions at 30 min, fire/water attached);
  - `replay` (the leakage-free state before each play);
  - `features`;
  - `e1` (session GAUC + rolling folds + session bootstrap);
  - `e2` (per-source and merged-set recall);
  - `e3` (the mood AUC);
  - `e4` (the list metrics, and a `Policy` protocol with `pick(session, rng)`);
  - `invariants`;
  - `report`.
- **The v1 baseline:** E1 of the v1 score, E2 per source, E3 of the CLAP axis, and E4 list
  metrics of **the logged v1 sessions**.
- The spike's ranker + policy stays as `reference_policy.py`, clearly marked as a
  reference, which phase 2 replaces.

**Subtleties:**
- **Only candidate-varying features** go into E1 models. Context constants (hour, "skipping
  right now") inflated the AUC in the spike. Keep a unit test that a feature constant
  within a session cannot change the GAUC.
- **Ranks split ties evenly** (the spike had an optimistic-tie bug that inflated
  co-listen).
- **Pools are recorded at serve time,** not recomputed afterwards (a spike bug that made
  «Микс» serve 99% unplayed).
- **The simulator is optimistic.** Always print its calibration on real v1 plays
  (predicted vs actual not-skipped) next to E4.
- **Mood labels:** export them once from the artifact's `labels` collection to
  `/mnt/data/musix-snapshots/labels/mood_labels.json` (track id → label; the clip map
  un-blinds them). They are not in git.
- **Vectors:** CLAP comes from the snapshot's Qdrant export. The MuQ/MERT files stay in the
  spike dir and are not needed (CLAP is kept).

**Done when:**
- `make recsys-eval SNAP=<date>` (also run by `make gates`) reproduces the spike's headline numbers within noise:
  - v1 score GAUC ≈ 0.49;
  - reference ranker ≈ 0.74;
  - CLAP axis AUC 0.99;
  - real v1 top genre / 10 ≈ 0.75;
- the invariants report 0 violations for the reference policy.

## E. Benches — `tools/bench/` (spec §5)

**Do:** `make bench`:
- brings up a **v1 copy** (the prod image `lyrics-search-musix`, container
  `musix-bench`, `127.0.0.1:18800`) on the snapshot working copy + the dev Qdrant;
- runs `http.py` (async load at 1/5/20 users, 5 min each);
- runs the Playwright HAR / stream-start / cold-start probes;
- samples RSS/VRAM;
- writes `tools/bench/report/<date>.{md,json}`.

**Subtleties:**
- **The request mix** comes from the prod container's access log
  (`docker logs musix | grep '"GET /api/v1'`). It only covers the time since the last
  restart, so take the counts on the day of the run and record the window in the report.
- **Auth for the copy:** mint a JWT for the owner's user id with the copy's own secret
  (v1 `AuthService`). Never reuse prod's secret or passwords.
- **VRAM:** the copy on GPU needs ~5 GB, which is not free.
  - Default: `FORCE_CPU=1`, with the model-bound endpoints (search, similar) marked
    "CPU — not comparable".
  - A GPU bench window needs the owner to pause llama-server. Ask before doing it.
- **Stream start under LTE:** Chrome CDP `Network.emulateNetworkConditions` (12 Mbit/s,
  70 ms RTT).
- **Android:** only if the phone is on the LAN (`adb`). Otherwise the section says
  "deferred to phase 4".

**Done when:** the report has every row of spec §5 (or an explicit "deferred" / "CPU"
note), and the copy is torn down afterwards.

## F. Design — `design/` (exit criterion 3)

**Do:**
- **`design/tokens/*.json` (DTCG):** colors (both themes, from `useColors` in
  `frontend/packages/musix-ui/src/index.jsx` and the CSS custom properties in
  `frontend/src/index.css`), typography, spacing/radius, glass, motion.
- **Generators:** `design/gen/build.py` → `gen/web/tokens.css`,
  `gen/android/MusixTheme.kt`, `gen/windows/MusixTheme.xaml`. `make design-check` fails on
  drift, and CI runs it.
- **Component specs:** `design/components/*.md`, one per musix-ui component (26 docs exist
  in `packages/musix-ui/docs/`: convert them and add measurements and states from the code),
  plus the composite surfaces from spec §6.3.
- **Golden screenshots:** `design/golden/`, via Playwright against the bench v1 copy (block
  E): every surface × phone 412×915 / desktop 1440×900 × dark / light.

**Subtleties:**
- **Parse, don't transcribe:** extract `useColors` palettes with a small JS→JSON script
  (node on the musix-ui source), so the tokens stay traceable. Hand-add only what lives in
  inline styles (accent `oklch(60% 0.18 270)`, the tab bar gradients), each with a
  `$description` naming its source.
- **Colors in two forms:** CSS keeps `oklch()`. Compose and XAML need sRGB, so convert
  `oklch → sRGB` in the generator (culori-style math, clamped) and unit-test a few known
  values.
- **Golden screenshots** use the owner's real library on the copy. They are **not
  committed** if they show the library: store them under
  `/mnt/data/musix-snapshots/golden/`, and commit only an index plus a fixture-library set
  taken on the e2e seed. Real screenshots are what the phase 4/5/7 reviews use.
- Fonts (Geist, Noto Sans, Playfair Display, JetBrains Mono, Noto Serif Display) are
  recorded as tokens. Their files are not vendored until a client needs them.

**Done when:**
- `make design` regenerates the three outputs identically;
- every musix-ui component has a spec;
- the golden set exists for both sizes and themes.

## Review focus (whole branch, at the end)

1. **Nothing touched v1 or prod:**
   - `git diff main -- app frontend scripts tests docker-compose*.yml deploy/nginx/musix.conf`
     is empty;
   - no writes under `/home/ivan/musix-db`, `qdrant_storage` or `cache/`.
2. **No prod data in git:** grep the diff for `acct_`, emails, lyrics lines and track
   titles. Snapshots, fixtures, labels and golden shots stay under
   `/mnt/data/musix-snapshots/`.
3. **Determinism:** gates and recsys-eval give identical numbers on re-run for the same
   snapshot.
4. **The dev stack is isolated:** ports `127.0.0.1:18xxx` only, its own project, volumes
   and network; `make down` leaves v1 running.
5. **CI runs without the home box:** the unit, contract and testcontainers tests need no
   GPU, no snapshot and no network beyond image pulls.
