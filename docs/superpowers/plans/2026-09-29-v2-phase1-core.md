# Phase 1 — Core: plan

> Native execution, blocks in order. Each block ends with a "done when" check, then a
> commit (Russian subject). Tests only for clear functionality: about 30 for this phase
> (the whole project budget is ~100).

**Spec:** `docs/superpowers/specs/2026-09-29-v2-phase1-core-design.md`.
**Everything lives under `v2/`.** The server is `v2/server/src/musix/`, contexts are in
`contexts/<name>/`, and the migrations are Alembic `0002…`. The old code is not touched.
**Goal:** the spec's exit criteria:
- budgets met;
- contract tests green;
- Kotlin/C#/TS clients compile;
- a library registers and plays end to end in every tier, with loudness.

## Global constraints

- Phase 0's constraints hold: prod is read-only, the dev stack is on `127.0.0.1:18xxx`,
  the GPU is not ours, and prod data stays out of git.
- **v2 media lives in `/mnt/data/musix-v2-media/`** (dev), never in v1's `media/`.
  - Library by reference: `/mnt/data/music` is mounted **read-only**.
  - Dev ingest runs on a **subset folder** of ~30 tracks: the full library costs ~94 GB and
    hours of CPU, so it waits for phase 3.
  - `MEDIA_RENDITION_BUDGET_GB` defaults to 150 (153 GB free today). Where the full
    renditions live is the owner's decision at phase 3.
- **Stack additions:**
  - server: `pyjwt[crypto]` (EdDSA), `argon2-cffi`, `mutagen`, `pyvips`, `blurhash`,
    `prometheus-client`, `opentelemetry-instrumentation-fastapi` (the OTLP exporter only
    when `MUSIX_OTLP_ENDPOINT` is set), `schemathesis` (dev);
  - image: `ffmpeg` and `libvips`.
- **Blocking I/O in async code** is caught by ruff's `ASYNC` rules, already on. That is the
  spec §11 "custom check"; no separate script.

## Task 1 — Skeleton: errors, telemetry, contexts, DB settings

**Do:**
- **Errors:** `musix/errors.py`, a domain hierarchy (`NotFound`, `Conflict`,
  `Unauthorized`, `Forbidden`, `Invalid`, `RateLimited`) mapped once to RFC 9457
  `application/problem+json`.
- **Logs:** structlog JSON with `trace_id`, `account_id` and `device_id` bound per request.
- **Metrics:** `/metrics` (Prometheus): request histograms per route template, WS gauge,
  queue depth.
- **Tracing:** OTel FastAPI instrumentation.
- **Layout:** `contexts/` with one package per context; the shared `infra/db.py` session
  dependency.
- **Postgres:**
  - roles `musix_api` / `musix_worker` with `statement_timeout` 5 s / 5 min, set by
    `ALTER ROLE` in migration 0002;
  - `idle_in_transaction_session_timeout=30s`, `max_connections=100` in the compose
    command.

**Subtleties:**
- **Metrics labels:** use the route template, not the raw path (id cardinality).
- **Errors inside the app:** every `HTTPException` is replaced by the domain errors. FastAPI's
  own 422 is mapped to problem+json as well.
- **Queue depth for `/metrics`:** `select queue_name, status, count(*) from procrastinate_jobs`,
  cached 5 s.

**Done when:**
- `make check` is green;
- `/metrics` answers;
- a 404 from any route is problem+json.

## Task 2 — Identity

**Do:**
- **Migration** `0002_identity`:
  - `citext`;
  - `accounts`, `devices`, `refresh_tokens`, `invites`, `instance`, `instance_settings`,
    `account_settings`.
- **Context `identity`:**
  - setup (the first owner + instance mode);
  - login (with a device descriptor) → access + refresh;
  - `POST /auth/refresh` (rotate; reuse of a rotated token revokes its family);
  - logout;
  - `GET/DELETE /devices`;
  - invites (create / list / revoke / register with a code);
  - `GET/PUT /settings`, which are synced.
- **nginx:** `limit_req` 5 r/min per IP with a burst of 5 on `/api/v2/auth/`.

**Subtleties:**
- **Keys:** the Ed25519 key pair and the HMAC media secret are generated on first start
  into `MUSIX_SECRETS_DIR` (dev: a volume), mode 0600.
  - The encryption key for secrets in `instance_settings` (the LLM API key) is a Fernet key
    in the same dir.
  - Never in the DB, never in git.
- **argon2id:** `argon2-cffi` defaults, tuned to ~50 ms on this box (measure once, record the
  params in a comment).
- **Access JWT claims:** `sub`, `dev`, `role`, `scope`, `exp` (15 min).
- **Refresh:** an opaque token, `secrets.token_urlsafe(32)`, stored as sha256; sliding
  60 days.
- **Owner / member:** mode `personal|shared` keeps v1's semantics. v1's server-mode admin
  account is not a listener; the migration maps it in phase 3.

**Tests (6):**
- login → refresh rotates;
- reuse of an old refresh revokes the family;
- an expired access → 401 problem;
- an invite is single-use;
- a member cannot call owner routes;
- deleting a device revokes its tokens.

**Done when:** the tests are green, and a curl login → refresh → devices flow works through
nginx.

## Task 3 — Library, scan, uploads, the ingest chain up to `register`

**Do:**
- **Migration** `0003_library`: `media_files`, `renditions`, `images`, `lyrics`, `artists`,
  `songs`, `albums`, `tracks`, `track_artists`, `change_log`, `uploads`.
- **Context `library`:**
  - `POST /library/scan` (owner: a folder grant);
  - `POST /uploads` / `PATCH /uploads/{id}` (`Upload-Offset`) / completion;
  - `GET /tracks?ids=`.
- **Worker tasks** (queue `ingest`): `scan_folder` → per file `hash` → `probe` → `tags` →
  `register`. Each is idempotent by sha256 (Procrastinate `queueing_lock` = sha256 + step),
  and each step enqueues the next.
- **Copied from v1 with its tests:** the artist split (`app/services/artist_split.py` → `contexts/library/artist_split.py`)
  and the lyric sanitizer.

**Subtleties:**
- **Scan:** compare (path, size, mtime) with `media_files` and hash only what is new or
  changed. Reuse phase 0's hash cache idea (the stored mtime/size per path).
- **Dedup:** a known sha256 skips everything but `register` (a second account's track row
  points at the same `media_files` row).
- **Upserts:** `INSERT … ON CONFLICT` everywhere; never select-then-insert. The `songs`,
  `albums` and `artists` keys are slugs (v1's `songs` slug scheme; albums unique on
  (album_artist, normalized title, year)).
- **`change_log`** row in the same transaction as every synced mutation, through one
  helper: `record_change(session, account_id, entity, id, op)`.
- **Uploads:** chunks append to `/mnt/data/musix-v2-media/uploads/<id>.part`. Completion
  verifies sha256, then moves the file to `media/<sha[:2]>/<sha>.<ext>`. MIME sniffing via
  ffprobe, not the extension.

**Tests (5):**
- the artist split cases from v1;
- scan skips unchanged files;
- the same file in two accounts gives one `media_files` row and two `tracks`;
- an upload resumes at the offset;
- a bad sha256 at completion → 400 and the part is kept.

**Done when:** scanning the 30-track subset registers every track, and a rescan does nothing.

## Task 4 — Media: loudness, renditions, images, signed delivery, manifests

**Do:**
- **Tasks:**
  - `cover`: embedded art → pyvips WebP 96/256/512/1024 + palette + blurhash;
  - `loudness`: ffmpeg `ebur128`, integrated LUFS + true peak + LRA;
  - `renditions` (queue `media`): `high` AAC-LC 320 first, then `economy` 128, and
    `lossless_compat` only for ALAC (→ FLAC) and Dolby/DTS (→ AAC);
  - the rendition budget.
- **`POST /playback/manifest`** {trackIds, network} → per track the URL + tier + codec +
  gains + size + fallbacks. The tier comes from the account settings (Wi-Fi `lossless`,
  cellular `high`, economy opt-in).
- **Signed URLs:** `/m/<sha>/<tier>.<ext>?e=&s=` (6 h) and `/i/<id>/<size>.webp` (long, immutable).
- **nginx njs** `verify.js`: HMAC-SHA256(path + exp) with the shared secret file, then
  `sendfile` with Range support.
- **App distribution:** `GET /download/{file}` (nginx alias) and `GET /app/{platform}/latest`
  from `downloads/manifest.json`.

**Subtleties:**
- **ffmpeg:** `-c:a aac -b:a 320k -movflags +faststart`, keeping 44.1/48 kHz. Multichannel is
  downmixed to stereo with `-ac 2`. Always `-map 0:a:0` (skip attached covers). Run it in
  the worker through `asyncio.create_subprocess_exec` with a timeout.
- **Gains:** `trackDb = -14 - lufs`. Positive gain is capped by `-1 - true_peak` (no
  clipping), and the client applies it. `albumDb` is the album's mean LUFS (computed at
  register time, when every album track has loudness).
- **Palette:**
  - k-means (k = 5) in Lab over a 64 px thumbnail with numpy;
  - the accent follows v1's browser rule. Port `accentColor` from `PlayerSection`: read
    main.jsx and copy the clamping constants.
- **njs:** `js_import` + `js_set $valid verify.check`, then `if ($valid = 0) { return 403; }`.
  The secret is read once from a file (the njs `fs` module at load). Expiry is checked in
  njs too.
- **Paths:** `/m/` maps to `/mnt/data/musix-v2-media/<sha[:2]>/<sha>/`. `lossless` is served
  from the original's path, and a `reference` file is served through its own read-only
  mount alias.

**Tests (5):**
- the tier choice per network and setting;
- the gain math (attenuation, the capped boost);
- a manifest URL passes the njs check through nginx, an expired or altered one is 403
  (integration, the compose nginx);
- the renditions of a fixture FLAC are AAC 320 / 128, playable by ffprobe;
- ALAC → `lossless_compat` FLAC.

**Done when:**
- every subset track has `high` + `economy`, loudness and cover variants;
- a Range request through nginx with a signed URL returns 206.

## Task 5 — Listening: events + stats, signals, playlists, settings

**Do:**
- **`POST /events/listens:batch`** (≤ 100): insert + an `account_track_stats` upsert in one
  transaction, idempotent per `clientEventId` (`ON CONFLICT DO NOTHING`, and the stats count
  only newly inserted rows).
- **Signals:** `POST /tracks/{id}/signals`, `GET /signals/state?trackIds=`. Charge and lock
  as v1: 1-day half-life, lock above 50%.
- **Playlists:** CRUD plus items with **fractional-index** positions (a base-62 key-between
  port of the well-known algorithm).

**Subtleties:**
- **Idempotency:** `INSERT … ON CONFLICT (client_event_id) DO NOTHING RETURNING id`. Stats
  are updated from the RETURNING set only, so a replayed batch changes nothing.
- **`end_reason`:** from the client; `completed` when played ≥ 90%.
- **Change log:** events do NOT write `change_log` (not synced); signals do (signalState),
  and so do playlists and settings.
- **NOTIFY** `musix_events` after commit, `{account_id, kind}` (phase 2's stream state
  consumes it).

**Tests (5):**
- a replayed batch is a no-op;
- stats match the events;
- signal charge / lock over time;
- fractional keys stay ordered through 1000 random inserts;
- moving a playlist item touches one row.

**Done when:** the tests are green, and a curl batch of 100 events < 30 ms locally.

## Task 6 — `/sync` and the realtime channel

**Do:**
- **`GET /sync?cursor=`:**
  - a keyset on `change_log(account_id, seq)`, ≤ 1000 per page, entities from spec §7;
  - no cursor → a full snapshot as upserts, streamed page by page;
  - tombstones for deletes.
- **`GET /api/v2/ws`:**
  - the first message is auth;
  - `sync.changed {cursor}`, `job.progress` / `job.done`, `instance.status`,
    `device.presence`;
  - a 25 s heartbeat, resume by `lastSeq`.

**Subtleties:**
- **Fan-out:** one Postgres channel `musix_events` with an `account_id` in the payload, and
  each api worker LISTENs once on a dedicated asyncpg connection, then routes to its
  sockets. It is simpler than a channel per account, and at ≤ 20 users the filter is free.
  Ruling vs spec §8: "a channel per account".
- **Snapshot consistency:** the full sync reads at one `seq` high-water mark, taken first,
  and returns it as the cursor, so changes during the dump arrive in the next delta.
- **`instance.status`:** a periodic worker task (60 s) probes the LLM endpoint and NOTIFYs
  on change only.
- **Job progress:** the ingest tasks update a `jobs` row, and NOTIFY on each 1% (throttled).

**Tests (4):**
- delta after a playlist edit;
- tombstone after a delete;
- a full sync during concurrent writes loses nothing (high-water mark);
- the WS gets `sync.changed` after a signal.

**Done when:** the tests are green, and an initial sync of the subset account returns every
track.

## Task 7 — BFF shapes, batch reads, ETags

**Do:**
- `GET /home` (library parts: recent, playlists, counts; phase 2 adds «Поток» and вайбики);
- `GET /library/summary`;
- `GET /albums/{id}`;
- `GET /artists/{id}/page` (discography from the account's own tracks);
- `GET /player/context/{trackId}` (lyrics + credits from tags; facts and badges in phase 2);
- `GET /albums?ids=`, `GET /artists?ids=`.

**Subtleties:**
- Sections are composed with concurrent queries (`asyncio.gather` on separate sessions from
  the pool).
- **ETag** = a hash of (account, the max `change_log.seq` relevant to the shape), computed
  before the body. A `304` never builds the body.
- A shape only ever returns the account's own tracks. Every query filters by `account_id`
  at the repo level, never in the router.

**Tests (2):** `If-None-Match` gives 304; another account's track is never returned.

**Done when:** each shape answers in < 50 ms locally on the subset.

## Task 8 — Contract, codegen, compile

**Do:**
- **Contract:** `make openapi`; schemathesis runs against the dev api (`--checks all`, the
  auth hook logs in).
- **Codegen** into `v2/contracts/codegen/{kotlin,csharp,ts}`:
  - `openapitools/openapi-generator-cli` (kotlin, kotlinx.serialization + okhttp);
  - `mcr.microsoft.com/openapi/kiota` (C#);
  - `openapi-typescript` (npm).
- **Compile:**
  - Kotlin with Gradle + JDK 21 (`/mnt/data/android/jdk21`);
  - C# in `mcr.microsoft.com/dotnet/sdk:9.0` (`dotnet build`);
  - TS with `tsc --noEmit`.
- `make codegen` + `make codegen-check` (drift).

**Subtleties:**
- Generated code is committed only as the generator config plus the lockfile of versions.
  The generated sources are **not** committed (they are big and noisy): CI regenerates and
  compiles.
- Pin the generator image tags.
- camelCase aliases must be set via `populate_by_name` + `alias_generator` so the OpenAPI
  shows camelCase.

**Done when:** the three clients compile, and schemathesis reports no failures on the
implemented routes.

**Subtleties:**

- `pg_stat_statements` top 10 after the run goes into the report. Fix any sequential scan it
  shows.
- The results go into `v2/tools/bench/report/<date>-v2-phase1.md` next to the v1 baseline.

**Done when:** every §10 budget is met, or the report says which one is not and why.

## Review focus (end of phase)

1. No route leaks another account's data: repo-level `account_id` filters, plus a test.
2. No blocking I/O in async code (ruff ASYNC clean); ffmpeg and hashing run only in workers.
3. Every synced mutation writes `change_log` in the same transaction.
4. Signed URLs can't be reused past expiry or for another path.
5. Secrets (Ed25519, HMAC, Fernet) never reach git or logs.
