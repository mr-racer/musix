# v2 phase 1 — exit bench (spec §10), 2026-09-30

`make bench-v2` on the dev stack (home box, 12 cores, CPU only), next to v1 prod. Raw
numbers: `2026-09-30-v2-phase1.json`. v1 baseline: `2026-09-29.md`.

## Setup

- **Dataset.** `bench@`: 6000 synthetic tracks (400 artists, 600 albums), 20k listens
  over 90 days, 20 playlists × 60, 200 signals. The rows come from ingest's own `register`
  and the listening/playlist services, so change_log and stats look real (8423 synced
  entities). Every track has its own `media_files` row. That row's rendition directory is
  a symlink to one of the 30 real dev-subset files, so manifests sign real files.
- **Load.** 20 users per route, closed loop, no think time (the v1 bench's model),
  through nginx, 20 s per route. Reads: 20 devices of `bench@`, the largest library.
  Writes: `bench-01…20@` (300 tracks each), so the 20 writers are 20 people. 20 devices
  of one account hammering the same stats rows is lock contention no real library has.
- **Stack.** api: uvicorn, 4 workers (spec §1). nginx keeps connections to the api alive.
  Postgres 18.
- **Stream start.** Chrome at phone size fetches the manifest (cellular → `high`, AAC 320),
  then `<audio>` plays the signed URL until 'playing'. LTE is 12 Mbit/s and 70 ms RTT
  through CDP throttling, as in the v1 baseline.

## What the bench found, and the fixes

| Found | Fix |
|---|---|
| 20 concurrent listen batches over the same tracks **deadlocked** (500s). Every other lock waited up to `deadlock_timeout`, so p99 sat at ~1 s. | The stats upsert takes rows in `track_id` order: one lock order for everyone. |
| The listen batch took 6 round trips (ownership check, insert, stats, notify, commit). | One statement: a CTE validates against the account's tracks, inserts `ON CONFLICT DO NOTHING`, folds only the inserted rows into the stats, and NOTIFYs. p95 at 10 events: 133 → 30 ms. |
| `max(seq) WHERE account_id = …` (every ETag) and the `/sync` delta scan walked the `seq` primary key backwards, filtering out 47k rows of other accounts (3–5 ms a call). | Migration 0008: change_log is keyed `(account_id, seq)`. Now 0.06 ms. |
| nginx opened a new upstream TCP connection per request. At ~1000 rps the ephemeral ports ran out in TIME_WAIT (**502** "Address not available"). | An `upstream` with `keepalive 64` and `resolve` (Docker DNS still re-resolved). `Connection` goes through a map, so WebSockets still upgrade. `proxy_set_header` moved to server level: a location-level one silently drops the inherited ones. |
| «Recent» sorted every stats row of the account behind a seq scan of tracks. | Index `(account_id, last_played_at DESC NULLS LAST)` + `EXISTS`. |
| `/home` counted distinct albums and artists on every request. It read tracks twice. | Counts are memoized per (account, change_log head), with the head taken from the ETag read. One `get_tracks` serves both sections. |
| One uvicorn worker (the dev default) was CPU-bound at ~150 rps on `/home`. | 4 workers, as spec §1 says. `/metrics` sums them through `PROMETHEUS_MULTIPROC_DIR`. |
| `@app.middleware("http")` costs a task and a stream per request. | A pure ASGI middleware. |
| The first runs showed ~1 s tails on every route. That was the bench itself: its RSS sampler ran `docker stats` synchronously on the load loop. | The sampler runs in a thread and reads per-process VmRSS (the budget is per worker). |

## Caveats

- **Load model.** Closed loop with no think time is a saturation test: 20 users here send
  more traffic than 20 real listeners by two orders of magnitude. It is the v1 model, so
  the two are comparable.
- **Stream start** measures the server and the network: manifest, then signed URL, then
  first decoded audio. It does not measure an app's UI. The files are AAC 320 from the dev
  subset. Real FLAC `lossless` on LTE is a phase-3 measurement.
- **Dataset.** The 6k tracks share 30 real media files, and album sizes are uniform.
  Lyrics are empty, so the player context carries no lyric text.
