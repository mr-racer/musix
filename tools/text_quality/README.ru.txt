Результат этапа

Повышать repetition penalty не следует. Для отдельного языкового редактора
перспективнее presence_penalty=0, но даже узкий лечащий промпт пока не прошёл
проверку для автоматического применения. В новой выборке из 64 фактов редактор
предложил семь прошедших структурные ограничения правок: пять полезных и две
вредных. Это оценка разработавшего решение ассистента по исходным материалам,
а не независимая человеческая разметка и не проверка истинности самих источников.

Поэтому MUSIX_STATIC_TEXT_EDITOR по умолчанию равен off. Подготовлены промпт,
подключение к трём сохранённым поверхностям, режим наблюдения и воспроизводимые
инструменты. Массовое исправление базы и развёртывание не выполнялись.

Материалы и ограничения аудита

Приватный снимок: /mnt/data/musix-snapshots/text-quality-audit-2026-11-11.
Эксперименты: /mnt/data/musix-snapshots/text-quality-penalties-2026-11-11.
Исходные тексты, идентификаторы коллекций, ответы модели и HTML для сравнения
хранятся вне git. В git находятся код, этот отчёт и обезличенные агрегаты.

Прочитаны 18 970 непустых обработанных фактов, 1 467 биографий, 4 005 строк
плеера, 3 501 опубликованный текст о звучании. Только у 1 603 фактов явно указан
нынешний qwen3.8-27b-ud-q3_k_xl; остальные нельзя приписывать этой модели.
Таблицы выгружались последовательно, без единого глобального снимка работающей БД.

Смешение алфавитов встретилось в 63 фактах, 10 биографиях, одной строке плеера
и одном тексте о звучании. Это кандидаты для проверки, а не число подтверждённых
ошибок. Старый checker отметил 103/1 603 фактов нынешней модели: длину, повтор
названия, подозрительные имена и алфавит. Большую часть смысловых ошибок такие
проверки не видят: ошибочное слово часто существует в русском языке.

Во всех 18 970 фактах отсутствовал source_url. Исходный английский факт при этом
сохраняется отдельно и связан с обработанным фактом. confirmed=true не является
независимым свидетельством: этот флаг проставляется самим пайплайном. У строки
плеера раньше не сохранялся выбранный ID исходного факта. У биографий часто есть
URL, но не сохранены использованные фрагменты и доказательства отдельных facets.

Обобщаемые классы ошибок

* Согласование, падеж и управление; правильное словарное слово в неверном контексте.
* Обычное английское слово внутри русской фразы; буквальный перевод идиомы с потерей
  части смысла. Наличие латиницы само по себе не ошибка: имена и названия нужны.
* Смешанные алфавиты, повреждённые имена и неуместная транслитерация.
* Подмена действующего лица, роли, типа произведения, причинности или уверенности;
  добавление правдоподобной детали, которой не было в источнике.
* Источник про другого исполнителя из-за ошибки поиска. Редактирование языка
  не исправляет неверно выбранную сущность и может сделать выдумку убедительнее.
* Служебные NO_DATA/think/Why/SKIP вместо содержательного текста.

Словарь замен под обнаруженные ошибки не включён. Пробные лексические правила
затрагивали лишь единицы из тысяч записей и не давали основания ждать переноса.
Морфология и LanguageTool пропускали контекстные ошибки; отдельная CPU-модель
коррекции меняла имена и вносила лишние изменения. Зависимости приложения
и сервер моделей ради этих опытов не менялись.

Сравнения на нынешнем локальном Qwen

Модель: qwen3.8-27b-ud-q3_k_xl, GGUF UD-Q3_K_XL, llama-server b10358-030ebb558.
Параметры менялись только в запросах. Серверные настройки не менялись.
Каждый факт редактировался отдельным запросом, без пакетной проверки нескольких.

1. Repetition penalty: 34 случая x 2 seed x 3 значения = 204 ответа. Корпус:
   24 факта (12 известных проблемных + 12 случайных), 6 строк с одним источником,
   4 биографических задания с фиксированными фрагментами.

   Значение             1.0       1.05       1.1
   Сломанный JSON/shape 0/68      2/68       7/68
   Смешанный алфавит    4/68      4/68       5/68
   Превышение длины    4/68      2/68       1/68

   Меньшая длина не компенсировала повреждение формата. Оставляем 1.0.
   Это диагностические счётчики, а не измерение грамматической/фактической точности.
   Менять глобальный presence_penalty по отдельному сравнению 0/.5/1.5 также
   оснований нет. Его исходное значение 1.5 сохранено для генераторов.

2. Прямой перенос редактора ассистента, минимальные JSON-замены, маскирование имён,
   общий фактологический редактор и требование цитат не решили проблему целиком.
   На первом holdout из 128 фактов общий редактор допустил 31 изменение: 12 полезных,
   11 вредных, 5 нейтральных и 3 смешанных. Все 31 просмотрены с исходным материалом.
   Дословная цитата подтверждает копирование источника, но не верность её трактовки.

3. Presence penalty только редактора: 64 контрольных случая x 2 seed x 3 значения
   = 384 ответа. Из них 24 пары «корректный/искусственно испорченный» и 16 отдельных
   стилевых контролей. При p=0 все 80 показов корректных/стилевых текстов остались
   без изменений после ограничений. При p=.5 допущено 2 лишние правки, при p=1.5 — 7.
   Это синтетические семейства, а не 128 независимых производственных документов.
   Результат использован только для выбора параметров следующего кандидата.

4. Более узкий языковой промпт: факты не исправляет и не дополняет, спорное отдаёт
   как unresolved. На отдельных контролях с p=0 все 80 корректных/стилевых показов
   сохранены; принято 40/48 правок испорченных вариантов. «Принято» означает прохождение
   структурных ограничений, а не автоматически доказанную правильность исправления.

   Затем открыт новый набор из 64 реальных фактов по ранее не использованным
   исполнителям: 32 текущей модели и 32 старых/неизвестных. Результаты:
   unchanged=46, repaired=7, rejected=8, unresolved=3. Восемь rejected затрагивали
   защищённые имена; один из unresolved не исправил заявленную ошибку.
   Просмотр всех семи допущенных: 5 улучшений и 2 ухудшения. Вред: потеря смысла
   «единственный хит» при переводе идиомы и порча согласования с существительным
   «компания». Этот результат не превращён в успешный тест после подбора исключений.
   Набор теперь считается открытым development evidence, а не будущим holdout.

5. Независимые CPU-классификаторы исследованы отдельно: multilingual NLI и RuCoLA.
   NLI обнаруживает некоторые явные противоречия, но на реальных музыкальных
   заметках также одобряет смену смысла и отвергает корректные переводы. RuCoLA
   замечает часть порчи грамматики, но не гарантирует сохранения значения.
   Порог по этим результатам не подбирался для production; модели в приложение
   не подключены. Их оценки 98 пар остаются диагностикой.

Одинаковый seed не делал запросы побитно воспроизводимыми: при повторе совпали
43/68 контрольных результатов. Различия cache/prefill могут менять генерацию;
единичные небольшие отличия не интерпретируются как доказанный прирост качества.
Исполнители для проверочных наборов исключались из уже использованных наборов.
Промпты/валидаторы, полные ответы, sampler probes и хеши сохранены по запускам.
Счётчики относятся к замороженным на момент запуска версиям. Последующее ужесточение
ограничений в рабочем коде не выдаётся за новый положительный результат на holdout.

Что подготовлено в приложении

prose_repair.py содержит один неизменный префикс и один запрос для одного текста
вместе с его материалом. Переменные, имена и ограничения идут после префикса.
Задача редактора — только язык и случайное смешение алфавитов. Он должен сохранять
голос, детали, роли, отрицания, причинность и степень уверенности. Вызов без источника
не выполняется; плохой ответ и ошибка транспорта не вызывают повторного запроса.

Параметры отдельного редактора: temperature=.1, repeat_penalty=1,
presence_penalty=0, thinking выключен, JSON schema, cache_prompt=true.
Обычные генераторы их не наследуют. Точный ответ также кешируется существующим
llm_cache; хеш включает промпт и параметры. Версия промпта и хеш исходного материала
сохраняются в quality рядом с draft, статусом, причиной и кандидатом.

Структурные ограничения отвергают изменение чисел, защищённых написаний,
новую смесь алфавитов/служебный мусор, повреждённые скобки и кавычки, новый
подозрительный перевод имени, сильное изменение длины/токенов. Даже если новый год
есть в источнике, это фактическая правка для отдельного рассмотрения. Отклонённый
кандидат сохраняется для анализа. Эти ограничения не доказывают смысловую эквивалентность.

Подключено к новым fact_refinements, artist_bios и song_vibes. Обработчик строки
плеера передаёт редактору только выбранный факт, сохраняет его FK и не выводит
на фронт источник, URL, quality или новый source ID. Запись исходных Songfacts/Genius
фактов сохраняет URL; для Genius это страница песни, не точная ссылка на annotation.
Для биографии в quality сохраняются переданные редактору фрагменты источника.
Старые строки автоматически не переписываются и не дополняются фиктивной историей.

MUSIX_STATIC_TEXT_EDITOR:
  off    — по умолчанию; новых вызовов редактора нет, старые пути ремонта сохранены.
  shadow — старый пайплайн формирует свой результат; один дополнительный вызов
           сохраняет предложение, отображаемый результат не меняет.
  apply  — экспериментальная возможность в рабочей ветке; применять к библиотеке
           сейчас не следует: проверка качества провалена. Один редактор заменяет
           старую цепочку исправлений. Для плеера не более двух генеративных вызовов
           всего; для биографии общий бюджет редактора = 1 даже при fallback источника.

Shadow — диагностический режим, не способ сэкономить на старых повторных вызовах:
в плеере возможны два старых запроса + один аудит. В apply третьего запроса нет.
Другие вызовы биографического pipeline (поиск, facets) здесь не менялись.
Миграция 0022 добавляет quality JSONB в три таблицы и nullable source_fact_id
в song_vibes. Публичные API-схемы не меняются. На production миграция не запускалась.

Единственная новая автоматическая текстовая чистка без модели удаляет отдельные
абзацы, целиком состоящие из протокольных NO_DATA/think-маркеров. Она не удаляет
эти слова из нормальной биографии. В снимке очистились 9 биографий; одна из них
состояла только из маркера и стала пустой. Это грамматику и факты не исправляет.

Остальные поверхности

Обычный чат и объяснение строки: не подключены к статическому редактору, новых
генеративных вызовов нет. Рискованные словарные исправления туда не добавлены.

Описание звучания в новом runtime: уже имеет генераторы, judge и редактор.
Следующий перенос должен заменять существующий редактор, не добавлять ещё один.
Числовые/аудио признаки — материал, биографические утверждения к ним неприменимы.
Названия островов вкуса и фразы «Волны»: уже имеют проверку языка, повтор и
детерминированный fallback; ещё один LLM-проход без отдельного измерения не нужен.
Квиз в базе этой ветки формируется детерминированно. Извлечение связей и facets —
структурированные данные: им нужны доказательства и проверка сущности, не редактор прозы.

Следующий обоснованный этап

Не продолжать строить лексический набор исключений. Сохранить исходные материалы,
показать кандидаты в shadow и разметить перенос на новых исполнителей человеком.
Если меньшая модель остаётся основным редактором, допускать возможность abstention
и отдельно измерять долю испорченных корректных текстов; фактология требует
проверки источника и сущности, а не уверенного ответа того же генератора.
Без нового положительного результата автоматическое применение не включать.

Воспроизведение

Из корня рабочей копии, Python из отдельного server env:
  python v2/tools/text_quality/penalty_eval.py prepare --help
  python v2/tools/text_quality/penalty_eval.py prepare-repair --help
  python v2/tools/text_quality/penalty_eval.py run --help
  python v2/tools/text_quality/penalty_eval.py summarize --help

Пример сравнения repetition penalty на уже замороженных cases.json:
  python v2/tools/text_quality/penalty_eval.py run \
    --cases /mnt/data/musix-snapshots/text-quality-penalties-2026-11-11/cases.json \
    --out /mnt/data/musix-snapshots/text-quality-penalties-2026-11-11/new-run \
    --parameter repeat_penalty --values 1.0 1.05 1.1 --seeds 2111 2811 \
    --stop-at 2026-11-12T00:00:00+00:00

Это исторический дедлайн: пример намеренно не должен запускать новые запросы после
03:00 МСК 12 ноября. Для нового согласованного опыта задать будущий stop-at.
run проверяет эффективные параметры через native /completion, не повторяет сбои,
пишет результат после каждого запроса и не смешивает разные протоколы в каталоге.
Старые открытые holdout не использовать для заявления о независимом подтверждении.

workflow_eval.py проверяет чередование writer/editor, а не пакетное выполнение.
Финальный языковой префикс тоже переиспользуется после writer-запросов: четыре
наблюдения и ограничения измерения записаны в experiment_results.json.
language_editor.py и evidence_editor.py сохраняют исследованные варианты промптов;
CPU-инструменты требуют отдельного experiment env с torch/transformers и локальных
весов. В server/ml проектах этих зависимостей не добавлено.
Веса и исследовательское окружение сохранены в /mnt/data/.cache/musix-text-quality
(около 2.9 ГБ); запущенных исследовательских процессов не осталось.

Проверки приложения (из v2/server; PYTHONPATH=src для env другой рабочей копии):
  python -m pytest -q tests/unit tests/contract tests/integration/test_knowledge.py
  mypy
Интеграционные тесты используют отдельные testcontainers, не dev/prod БД.
Alembic upgrade -> downgrade 0021 -> upgrade проверен на отдельном Postgres 18.
Итоговая проверка: 66 server unit/contract/knowledge integration тестов,
3 теста инструментов, Ruff для изменённых файлов и mypy для 234 server файлов — успешно.
