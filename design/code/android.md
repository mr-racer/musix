# Android: как предложить и собрать экран

Одна страница для агента, который берёт следующий экран телефона (2026-11-14). Решения владельца —
в `preferences.md` от 2026-11-14; полный план — `docs/superpowers/specs/2026-11-14-android-component-library-design.md`.

## Что прочитать, по порядку

1. `README.md` этой папки — что побеждает при конфликте, правило «сначала макет».
2. `preferences.md` — слова владельца по датам. Читать до предложения, дописывать после каждого раунда.
3. **Эталон экрана**: `design/reference/<экран>/` (`README.md`, `markup.html`, `logic.js`) и
   `screens/<экран>.md`; живой web — `web/src/<экран>/` (логика и данные берутся оттуда).
4. **Спека библиотеки** `docs/superpowers/specs/2026-11-14-android-component-library-design.md`:
   - §8 — строка своего экрана: эталон, что берёт из библиотеки, что строит в неё, что остаётся своим,
     какие v1-детали уходят;
   - §5.1 — правило входа: в библиотеку — поведение или вид, нужный ≥ 2 экранам; остальное — `internal`
     в модуле экрана; §5.3 — что точно остаётся в экранах;
   - §6 — таблица компонентов, §13 — что уже собрано;
   - §9.1 — рутина экрана, §10 — проверка.
5. Правила телефона: `layout.md` (телефон, шиты), `motion-and-performance.md` (что может двигаться,
   бюджеты), `surfaces.md`, `typography.md`, `components.md`.
6. Код: `android/core/designsystem/` — слои (корень = основа, `motion`, `gesture`, `surface`,
   `control`, `content`; `legacy` — уходящее v1). Что есть сейчас — реестр «Витрины»
   `android/feature/catalog/src/main/kotlin/ru/musixai/app/feature/catalog/Entries.kt`; живьём — в APK:
   Настройки → «Версия» семь раз → «Витрина компонентов» (или `musix://catalog`).
7. Пример готового телефонного экрана — главная: `docs/superpowers/specs/2026-11-13-android-home-r3-design.md`
   и `android/feature/home/`. Общий ребилд — `docs/superpowers/specs/2026-11-13-android-rebuild-design.md`.

## Что должно быть в предложении экрана

Экран с web-эталоном — **без HTML-макета**: эскиз в чате → Compose → APK (владелец, 2026-11-14). Экран без
эталона (плейлист, игра, вход) — эскиз, и сборка только после «да».

- Текстовая схема раскладки телефона (412 dp; что меняется на 360 и 448).
- Состояния: загрузка, пусто, ошибка, длинный текст, 1 и 1000 элементов, без сети.
- Шиты и меню: что открывается и откуда. Смена страниц — общая, из оболочки (фокус с размытием, как в
  web); свою экран не делает.
- Таблица «берёт из библиотеки / строит в библиотеку / своё» с проверкой правила входа.
- Вибрация каждого жеста — из словаря `HapticCue` (9 сигналов, только от пальца).
- Что двигается и когда затихает: в покое — ни кадра; только сдвиг, масштаб, прозрачность.
- Какие v1-детали (`legacy`) этот экран отпускает.

## Как собирать

- Сначала недостающие широкие компоненты — в `core/designsystem`, каждый с карточкой в `Entries.kt`;
  потом экран из них.
- Слой импортирует только нижние, `legacy` — только из списка `LayerRulesTest`: переехавший экран
  убирается из списка.
- Тесты — только ключевые (владелец, 2026-11-14): логика и правила, не каждый вид.
- Версия: каждый экран +0.1 к `versionName` и +1 к `versionCode` (2.3.0 / 12 — этап A).
- Проверка: `./gradlew testDebugUnitTest :app:assembleRelease`; эмулятор `musix-rebuild-emu`
  (`emulator-5556`) в обеих темах. Плавность и вибрацию оценивает только телефон.
- APK владельцу — release-сборка с релизным ключом (подпись должна совпасть с опубликованной). На сайт —
  только по его слову.
- Снимки реальной библиотеки — только в `/mnt/data/musix-snapshots/`, не в git.
- Код, комментарии и коммиты — по-английски; интерфейс и документы — по-русски.
