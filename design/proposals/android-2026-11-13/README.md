# Android: основа и первый телефонный макет

Дата: 2026-11-13. Ветка `android-rebuild`, checkout `/mnt/data/android-rebuild`,
база `design-refresh` (`92d5c7a`).

## Статус

Подготовлен **APK основы 2.1.1 / versionCode 9** и телефонный HTML этапов 1–2:
каркаса и плеера «Кино». **Полная переделка приложения ещё не завершена.**
Владелец одобрил общую идею и запросил полировку. Последним уточнением того же дня
он закрепил первоначальный **Dream как сырой, но в целом подходящий ориентир**:
его [неизменная копия](baseline/README.md) отделена от текущих правок.
В текущем HTML выполнен общий проход типографики и размещения, возвращены исходные
Steps с Richbox, подготовлен [первый отдельный раунд главной](home-review/README.md).
Это предложения для просмотра, не окончательная приёмка всех экранов.
Новая телефонная компоновка ещё не перенесена в Compose; этот раунд не меняет APK 2.1.1.

В APK этой итерации: актуальные генерируемые токены `design-refresh`, слой девяти
типов вибрации, ограничение частоты, сохраняемая настройка «Тактильный отклик»,
подключение отклика к play/pause и реакциям, физические пружины и зависимости для
следующих компонентов. В 2.1.1 общий `LiquidGlass` переведён на Haze 2.1 / haze-glass:
`GlassStyle.clear`, отдельный источник фона, синхронизация с темой приложения.
Экран входа, поиск и импорт получают фон через `GlassScene`. Экраны сохраняют
нынешнюю компоновку; изменения HTML-плеера ещё не входят в этот APK.

## Что проверить в HTML

В боковой панели, а на телефоне под макетом:

- размеры 360×780, 412×915 и 448×998;
- очередь из 1, 4 и 1000 строк (1000 — явно обозначенное повторение четырёх песен);
- навигация А — остров, Б — нижняя панель;
- свайп обложки: А 380/34, **Б 240/25, масса 1.15 — по умолчанию**, В 520/34; сопротивление на краях,
  возврат до порога, смена по скорости, соседняя обложка во время жеста;
- раскрытие мини-плеера тапом и жестом, сворачивание за верхнюю область;
- игра/пауза, секционный seek с волной, длинное название, загрузка, ошибка,
  пустое состояние, отсутствие сети/профиля звука, другое устройство;
- шиты «О песне», очередь, добавление в плейлист и «Слушать на…»;
- перестановка и смахивание очереди, отмена удаления, запрет удаления играющего трека;
- огонёк/вода и однократный всплеск, стопка тостов, управление с клавиатуры.
- состояния ассистента: до вопроса, работа, готовый ответ, ошибка; настоящая
  последовательность шагов по вопросу, остановка и повтор;
- шесть состояний главной; поиск «Библиотека / ИИ», сфера, стопки, фонотека и неделя.

## Проход типографики и компонентов

| Найдено | Изменение |
|---|---|
| Разные случайные размеры 10–14 px, искусственный курсив | Общая шкала: 13 px подписи, 15 px текст, 18/24 px заголовки; встроены Noto Sans italic и 600 |
| «Припев» оранжевым по центру между таймкодами | Geist 13 px под началом реального раздела с риской; отдельная строка времени JetBrains Mono; края ограничены seek |
| Вместо Steps — упрощённые символы и маленький текст | Исходный `createRichbox` из неизменённого `vendor/`, размеры/движение витрины; этапы и ответ Noto Sans 15 px |
| Вопрос, процесс и ответ имели слабую иерархию | Вопрос — заголовок; шаги идут по одной оси, ответ на открытом фоне; поле ввода закреплено над мини-плеером |
| Название и артист на «Стене» заходили друг на друга | Две отдельные строки на общей нижней растяжке обложки; исправлены размеры и отступы |
| Мелкие подписи списков, шитов, текста обложки и пустых состояний | Единые роли шрифтов и межстрочные интервалы; заголовки, подписи и действия разведены |
| Закрытая обложка могла остаться поверх другой страницы | Видимость карточек закрывается после сворачивания, перелёт сохраняется |
| Этапы могли продолжать анимацию за другим экраном | Richbox и перелив останавливаются при скрытии; отменённый ответ не появляется позже |

Исходный `vendor/` побайтно не меняется. Ограничение Richbox в §6.2 относится к
сценарию скачивания; **оно не исключает Richbox внутри принятых Steps**. Steps
доступны на странице ассистента и в шите вопроса о песне. Витрина задаёт три этапа
через 1300 мс, вход строки 300 мс, появление ответа 420 мс; автособытия без вибрации.
Непрерывная волна и мягкая физика обложки из предыдущего раунда сохранены.

Остальные принятые компоненты распределены по этапам, а не объявлены уже собранными:
JoiPro — событие библиотеки, MultiStep — импорт/первый запуск, CodeField — вход.
Полная библиотека, артист, плейлист, три вида ответов ассистента, игра, настройки и
первый запуск требуют подробных раундов по таблице §5.2. Нативная реализация каждого
экрана идёт после его отдельной приёмки.

## Полировка по отзыву владельца

- Сыгранная волна одна на всю линию: общая фаза, нет разрывов на границах разделов.
  Фоновые блоки, припевы и точки сохранены; на паузе линия прямая.
- Приехавшая обложка остаётся тем же DOM-элементом. Фон и метаданные обновляются
  в начале перехода, обложки подготовлены заранее; в конце нет замены картинок.
- Мягкая пружина основная: небольшая инерция, подъём 5 px, наклон до 0.9°,
  податливость при нажатии. Новая команда продолжает текущую скорость. Соседи
  плавно исчезают у края и не торчат по бокам в покое.
- Убрана отдельная play/pause полного плеера. На обложке подсказка первого
  использования, сохраняемая локально после нажатия; мини-плеер сохраняет кнопку.
- Haze / haze-glass подтверждён владельцем. `glass.css` — автономный браузерный
  аналог материала, **не Android-шейдер**. В APK работает настоящий Haze.
- Принятые исходники `vendor/` сохранены побайтно.

## Воспроизведение сборки и проверок

```bash
cd /mnt/data/android-rebuild

cd android
./gradlew :app:assembleRelease :app:assembleDebug :app:assembleDebugAndroidTest testDebugUnitTest
./gradlew :core:designsystem:recordRoborazziDebug --tests '*GalleryScreenshots'
adb -s emulator-5556 install -r app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5556 install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s emulator-5556 shell am instrument -w \
  -e class ru.musixai.app.FoundationSmokeTest \
  ru.musixai.app.dev.test/androidx.test.runner.AndroidJUnitRunner
```

`build.py` требует установленные WEB-зависимости для шрифтов; в этой сессии
`web/node_modules` — ссылка на уже установленные зависимости checkout `v2`.
WEB build не выполнялся. Kotlin-клиент генерируется из существующего контракта.
Исправлена прежняя ошибка генератора: сериализаторы дат и UUID объявляются на
уровне файла, чтобы работать внутри коллекций, включая `LibrarySummaryOut.albumLast`.
Формат API и сам контракт не меняются. Регрессионный тест проверяет round trip дат.
`make design` теперь только генерирует токены; старое извлечение V1 вынесено в
`make design-extract-v1`, поскольку его исторического frontend здесь нет.

## Осталось

- Отдельная приёмка полировки каркаса/«Кино» и перенос в Compose.
- Подробный разбор главной по подготовленному HTML, затем макеты и реализация
  этапов 4–10; pairing требует отдельной серверной спеки.
- Полноценный playback, handoff между двумя авторизованными устройствами,
  кнопки виджетов и воспроизведение альбома из Auto: в свежем AVD нет аккаунта
  с музыкой. Эти сценарии не объявляются пройденными.
- Macrobenchmark открытия плеера/«Стены»/перелёта, отсутствие кадров в покое,
  10 минут воспроизведения, thermalservice и вибрация — на Pixel 9 Pro владельца.
  CPU-эмулятор `musix-rebuild-emu` использует SwiftShader без доступа к GPU;
  результаты его запуска не подменяют измерения реального телефона.
- Публикация для остальных пользователей — только отдельным решением владельца.

Незавершённая работа `design-refresh` не коммитилась: новая ветка создана от
последнего коммита; из актуального worktree сохранены только уже существовавшие
нейтральные формулировки в `preferences.md` и `screens/home.md`. Production checkout
сохраняет прежние изменения; каталог предложения там — ссылка на этот worktree.
